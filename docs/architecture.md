# Архитектура

## Принцип

Позиция — центральный объект корпуса. Четыре 32-битные доски упаковываются в два
64-битных значения; сторона хода хранится отдельно и входит в канонический ключ.

```text
white64 = whiteMen | (whiteKings << 32)
black64 = blackMen | (blackKings << 32)
key = sideToMove:white64:black64
```

Одинаковая расстановка при ходе белых и при ходе чёрных считается двумя разными
позициями.

## Планируемые слои

- `core` — доска, правила, ходы, FEN и PDN;
- `corpus` — импорт, дедупликация позиций и индексы переходов;
- `storage` — опубликованный read-only корпус и локальные партии;
- `analysis` — статистика, дебюты, комбинации и аномалии;
- `ui` — PWA/Android-интерфейс;
- `neural` — локальная оценка позиции, когда будет подготовлена выборка.

## Модель корпуса (следующий этап)

```text
positions(id, key, white64, black64, side_to_move)
games(id, headers, result, source)
game_plies(game_id, ply, position_id, move_code)
transitions(position_id, move_code, next_position_id, counters...)
```

Исходный PDN и AST должны храниться отдельно для экспорта без потери комментариев,
вариантов и аннотаций. Цепочка позиций не заменяет точный код хода.
